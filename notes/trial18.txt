1. The Core Problem

Financial data is non-linear. Tickers are reused, companies change names, and identifiers (FIGIs) evolve. 
A simple ticker -> price lookup fails in edge cases like:

    Symbol Changes: Facebook (FB) becoming Meta (META).

    Ticker Reuse (The Gap): FB (Facebook) disappearing in 2022 and reappearing as FB (ProShares ETF) in 2025.

    Dead SPACs: CCIV existing only for 18 months before merging into LCID.

    Delistings: Companies like AMBC or ATE that vanished years ago.

2. The Solution Architecture

This pipeline reconstructs the complete "Life Story" of every instrument by stitching together point-in-time 
data from Polygon.io. It enforces FIGI (Financial Instrument Global Identifier) as the single source of truth.
Data Models
A. Instrument (The Entity)

Represents the unique financial asset (e.g., "Meta Platforms Inc").

    Unique Key: composite_figi

    Purpose: Stores static metadata (CIK, Name, Type) for the current or final state of the asset.

B. TickerMap (The Timeline)

Represents the state of that asset over time.

    Foreign Key: Links to Instrument.id.

    Fields: ticker, valid_from, valid_to, change_event_type.

    Purpose: Allows you to query "What was Ticker X on Date Y?" and get the correct instrument_id.

3. Key Algorithms & Fixes implemented
A. The "Heartbeat Anchor" Strategy

Problem: A binary search from 2004 to 2025 sees "Empty" at the start and "Empty" at the end for dead SPACs (e.g., CCIV), 
causing the script to skip them entirely. Fix: We inject heuristic "Heartbeats" (e.g., 2015-06-01, 2021-01-15) into the search.

    Before: Probe(2004) -> None, Probe(2025) -> None. Result: SKIP.

    After: Probe(2004) -> None, Probe(2021) -> FOUND! -> Drill down to find start/end dates.

B. The "FIGI Stitcher"

Problem: API returns separate timelines for FB and META. Fix:

    We flatten all ticker timelines.

    We group by FIGI.

    We sort chronologically.

    If Ticker A (FB) and Ticker B (META) share a FIGI, we link them:

        Event: SYMBOL_CHANGE

        previous_composite_figi: Inherited from the prior segment.

C. Ticker Reuse Handling

Problem: FB (Meta) and FB (ETF) share the same ticker string but are different entities. 
Fix: The resolve_history function detects if the FIGI changes mid-stream. It splits the history 
into two distinct segments. The Database Ingestion phase then maps them to two different instrument_ids.



5. Usage Logic (How to Query)

To find the correct Instrument ID for a given trade:
SELECT instrument_id 
FROM ticker_map 
WHERE ticker = 'FB' 
  AND '2015-01-01' BETWEEN valid_from AND valid_to;
-- Returns: ID for Meta Platforms

SELECT instrument_id 
FROM ticker_map 
WHERE ticker = 'FB' 
  AND '2025-07-01' BETWEEN valid_from AND valid_to;
-- Returns: ID for ProShares ETF
